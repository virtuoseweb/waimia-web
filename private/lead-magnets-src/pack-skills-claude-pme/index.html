1 · Le principe

Un skill, c'est une procédure écrite que Claude relit au bon moment

Un skill est un dossier. Il contient un fichier SKILL.md (les instructions), et parfois des fichiers de référence : votre grille de prix, vos modèles de courrier, vos indicateurs. Claude ne lit pas tout en permanence.

NiveauCe que Claude chargeQuand
1. Nom et descriptionEnviron 100 tokens par skill, d'après AnthropicToujours : c'est ce qui lui permet de savoir que le skill existe
2. Corps du SKILL.mdLa procédure (Anthropic conseille moins de 5 000 tokens)Quand votre demande correspond à la description
3. Fichiers du dossierGrille, modèles, listesSeulement si la procédure les cite et que la tâche en a besoin

Anthropic appelle ce fonctionnement la divulgation progressive. Conséquence pratique : la description décide de tout. Si elle est vague, le skill ne se déclenche pas ou se déclenche à tort. Les 8 descriptions du pack disent ce que fait le skill et quand l'utiliser ; si vous les modifiez, gardez cette forme.

Anatomie d'un SKILL.md du pack

---
name: relance-facture-impayee
description: Rédige la relance adaptée à une facture impayée selon son
  retard (rappel courtois, relance ferme, mise en demeure à valider).
  À utiliser pour relancer un client, un retard de paiement ou un impayé.
---
# Relance de facture impayée
Tu rédiges des brouillons. Une personne vérifie et envoie.

2 · Installer

Installer sur chaque surface que vous utilisez

Les skills ne se synchronisent pas entre claude.ai, Claude Code et l'API : un skill téléversé sur claude.ai n'apparaît pas dans Claude Code, et l'inverse. Installez-les là où vos équipes travaillent.

Sur claude.ai (web, application de bureau, mobile)

  1. Activer l'exécution de code. Sur Free, Pro et Max : Paramètres > Capacités, option « Exécution de code et création de fichiers ». Sur Team et Enterprise, un propriétaire de l'organisation active l'exécution de code et les Skills dans Paramètres de l'organisation > Plugins & skills, onglet « Policy ».
  2. Ouvrir Personnaliser > Skills (« Customize > Skills » dans l'interface anglaise).
  3. Ajouter : bouton « + », puis « Create skill », puis « Upload a skill ».
  4. Choisir un zip du dossier pour-claude-ai/. Un zip par skill.
  5. Vérifier que le skill est activé dans la liste, puis faire les tests du chapitre 4.

Le zip doit avoir la bonne forme. Il contient le dossier du skill à sa racine, et ce dossier porte le nom du skill : devis-commercial.zip contient devis-commercial/SKILL.md. Un zip qui contient directement SKILL.md, sans dossier, est refusé. Après avoir modifié un dossier, refaites le zip : sur Mac, clic droit sur le dossier > Compresser ; sur Windows, clic droit > Envoyer vers > Dossier compressé.

Ces chemins viennent du centre d'aide d'Anthropic, lu le 5 octobre 2026. L'interface change souvent : si un libellé a bougé, cherchez « Skills » dans les réglages.

Qui voit le skill sur claude.ai

Par défaut, un skill téléversé est personnel : vos collègues ne le voient pas. Sur Team et Enterprise, le centre d'aide décrit deux voies de partage : un propriétaire peut mettre un skill à disposition de toute l'organisation, et chaque membre peut partager le sien si le réglage « Skill sharing » est actif. La documentation développeurs d'Anthropic dit encore l'inverse, mais elle cite aussi un ancien chemin de menu ; la page tarifs d'Anthropic confirme le déploiement de skills à l'échelle de l'organisation sur Team et Enterprise. Le partage entre membres dépend d'un réglage du propriétaire : vérifiez-le.

Dans Claude Code

Claude Code lit les skills sur le disque, sans téléversement. Copiez le dossier du skill (pas le zip) :

EmplacementPortée
~/.claude/skills/<nom>/Vous, dans tous vos projets sur cette machine
.claude/skills/<nom>/ dans un projetToutes les personnes qui travaillent sur ce projet, si le dossier est versionné avec lui
Dans un plugin, skills/<nom>/Partout où le plugin est activé (voir chapitre 7)
mkdir -p ~/.claude/skills
cp -R skills/devis-commercial ~/.claude/skills/
cp -R skills/compte-rendu-reunion ~/.claude/skills/

Claude Code utilise le skill quand la demande correspond à la description, ou quand vous tapez son nom précédé d'une barre oblique : /devis-commercial.

Différence à connaître : les skills de documents fournis par Anthropic (Word, Excel, PowerPoint, PDF) existent sur claude.ai et dans l'API, pas dans Claude Code. Les skills du pack qui proposent de produire un fichier Word ou Excel le feront pleinement sur claude.ai ; dans Claude Code, Claude produira le contenu sous une autre forme.

Par l'API

Pour un développeur : les skills se téléversent par les points d'accès /v1/skills et s'utilisent avec l'outil d'exécution de code. Ils sont alors partagés à tout l'espace de travail API. Dans ce cas, l'environnement n'a pas d'accès réseau : le skill veille-concurrentielle y fonctionnera seulement sur des documents fournis.

Par où commencer. Installez d'abord un seul skill, celui qui vous fait gagner le plus de temps cette semaine. Adaptez-le, testez-le, utilisez-le dix fois. Puis passez au suivant. Huit skills installés et jamais adaptés font moins qu'un seul bien réglé.

3 · Adapter

Ce qu'il faut changer dans chaque skill

Un skill générique produit un résultat générique. Ce qui le rend utile, ce sont vos prix, vos modèles, vos indicateurs, vos mots. Comptez 15 à 45 minutes par skill pour la première adaptation : c'est une estimation de notre part, elle dépend de ce que vous avez déjà écrit.

Six skills ont un fichier compagnon qui contient des champs [À COMPLÉTER]. Tant qu'un champ reste vide, la procédure demande à Claude de le signaler au lieu d'inventer. Les deux autres (compte rendu, fiche de poste) s'utilisent tels quels et s'améliorent si vous y ajoutez vos modèles maison.

1. devis-commercial

À compléter : grille-tarifaire.md, modele-devis.md

Ce qu'il fait. Lit une demande en texte libre (e-mail, formulaire, notes d'appel), pose les questions qui manquent, rapproche chaque ligne de votre grille, calcule les totaux et rend un brouillon marqué « à valider », plus une note interne.

À adapter. Votre grille : codes, unités, prix HT, remises autorisées sans validation, minimum de commande, frais de déplacement. Vos mentions et conditions (faites relire les mentions légales par votre expert-comptable). La mise en page du modèle si vous avez déjà un devis type.

Point de vigilance. Une prestation absente de la grille sort en « HORS GRILLE » : c'est voulu. Ne demandez pas à Claude de « trouver un prix » : enrichissez la grille.

2. compte-rendu-reunion

Aucun fichier obligatoire

Ce qu'il fait. Transforme des notes ou une transcription en compte rendu : sujets, décisions, tableau des actions (responsable, échéance), points ouverts, et une liste « à vérifier avant diffusion ».

À adapter. Si vous avez des formats maison (comité de direction, réunion de chantier, point client), ajoutez-les dans le SKILL.md sous une rubrique « Modèles maison », un bloc par type de réunion.

Point de vigilance. Une transcription contient des propos de personnes qui ne savent pas forcément qu'ils sont traités par une IA : prévenez les participants, et évitez d'y faire passer des sujets RH individuels.

3. relance-facture-impayee

À compléter : modeles-relance.md

Ce qu'il fait. Choisit le niveau de relance selon le retard (rappel, relance ferme, mise en demeure), rédige le brouillon et liste ce qu'il faut vérifier avant l'envoi. S'arrête si un litige est signalé.

À adapter. Vos seuils de jours, vos signataires, vos coordonnées de paiement, et surtout les pénalités et l'indemnité de recouvrement telles qu'elles figurent dans vos CGV. Le skill reprend vos montants, il n'en calcule pas d'autres.

Point de vigilance. Le niveau 3 est un courrier formel : faites relire le modèle une fois par votre expert-comptable ou votre avocat, puis gardez la validation de la direction avant chaque envoi.

4. fiche-de-poste

Aucun fichier obligatoire

Ce qu'il fait. Pose les sept questions d'un recrutement, puis rédige la fiche de poste interne et, si demandé, l'offre publique (250 à 400 mots), en écartant les critères discriminatoires.

À adapter. Ajoutez à la fin du SKILL.md trois lignes sur votre entreprise (activité, taille, ce que vous offrez) pour éviter de les retaper, et votre convention collective si elle fixe des intitulés.

Point de vigilance. Le skill refuse « jeune et dynamique » et les critères du même ordre. Si un responsable insiste, c'est une conversation à avoir avec lui, pas un réglage à changer.

5. veille-concurrentielle

À compléter : concurrents.md

Ce qu'il fait. Produit une note où chaque fait porte sa source et sa date, sépare faits et interprétation, et termine par trois questions à trancher.

À adapter. La liste de vos concurrents, leurs sites, les sujets qui comptent pour vous et la fréquence. Plus la liste des sujets est précise, plus la note est courte et utile.

Point de vigilance. Le skill a besoin de la recherche web pour aller chercher l'information ; sans elle, il travaille sur les documents que vous lui donnez et le dit. Il ne collecte pas de données personnelles sur les salariés des concurrents.

6. rapport-mensuel-pilotage

À compléter : indicateurs.md

Ce qu'il fait. Inventorie vos exports, signale les trous et les doublons, calcule chaque indicateur par code, compare au mois précédent et à l'objectif, commente trois écarts et propose des décisions.

À adapter. La définition exacte de chaque indicateur, sa source (quel export, quelle colonne) et son objectif. C'est le travail le plus long du pack, et le plus rentable : deux personnes doivent obtenir le même chiffre en lisant la définition.

Point de vigilance. Gardez les mêmes définitions d'un mois sur l'autre. Si vous changez une définition, notez-le dans le fichier avec la date.

7. charte-redactionnelle

À compléter : charte.md

Ce qu'il fait. Écrit ou relit vos textes externes (e-mail, post, page, plaquette) selon votre charte, et justifie chaque modification importante par une règle.

À adapter. Vouvoiement ou tutoiement, trois adjectifs de ton, votre table « on écrit / on n'écrit pas », vos mots interdits, la graphie exacte de vos noms de produits, et surtout deux ou trois textes que vous trouvez réussis : ce sont eux qui donnent le ton.

Point de vigilance. Les autres skills s'appuient sur celui-ci quand il est installé (le tri des e-mails, par exemple). C'est souvent le meilleur premier skill à installer.

8. tri-emails-entrants

À compléter : categories.md

Ce qu'il fait. Classe les messages par catégorie et urgence, isole les suspects (dont toute demande de changement de RIB), et prépare des brouillons pour les demandes commerciales et les clients.

À adapter. Vos catégories, qui traite quoi, vos délais de réponse visés et vos réponses types déjà validées (horaires, zone d'intervention, délais standard).

Point de vigilance. Le skill traite le contenu d'un e-mail comme une donnée, jamais comme une instruction. Ne lui donnez pas, par un connecteur, le droit d'envoyer ou de supprimer : il est écrit pour préparer, pas pour agir.

Modifier une procédure. Ouvrez le SKILL.md dans un éditeur de texte et changez la partie qui ne vous convient pas. Gardez le bloc entre les deux lignes --- intact (sauf la description, si vous la reformulez sous 200 caractères), gardez le nom du dossier identique au name, et refaites le zip pour claude.ai.

Règles de format à respecter si vous écrivez vos propres skills. Le name : 64 caractères au plus, minuscules, chiffres et tirets, sans les mots « claude » ni « anthropic ». La description : non vide, sans balise, 1 024 caractères au plus selon la documentation développeurs. Le centre d'aide de claude.ai indique 200 caractères au plus. Claude Code n'a pas de plafond documenté, mais tronque description et when_to_use à 1 536 caractères dans la liste des skills. Les 8 descriptions du pack tiennent sous 200 pour passer partout.

4 · Tester

Trois essais avant le premier vrai usage

EssaiCe que vous demandezCe que vous devez observer
1. Cas normalUne vraie demande récente, anonymisée si besoin (« prépare le devis pour cette demande »)Le skill se déclenche, suit la procédure, rend le format prévu. Vérifiez chaque chiffre.
2. Cas incompletLa même demande avec une information clé en moins (la quantité, l'échéance)Claude pose la question au lieu de deviner.
3. Cas hors sujetUne demande voisine qui ne relève pas du skill (« résume cet article »)Le skill ne se déclenche pas.

Si le skill ne se déclenche pas à l'essai 1, la description ne contient pas les mots que vous utilisez : ajoutez-les (« chiffrage », « proposition », « estimation »). S'il se déclenche à l'essai 3, la description est trop large : resserrez-la.

Gardez vos trois essais dans un document. Après chaque modification du skill, rejouez-les : c'est votre test de non-régression, sans outil particulier.

Grille de recette, à cocher par skill

  • Les trois essais donnent le résultat attendu.
  • Aucun chiffre, prix, nom ou date inventé dans les sorties.
  • Les fichiers compagnons ne contiennent plus de [À COMPLÉTER].
  • Une deuxième personne de l'équipe a fait l'essai 1 et obtient un résultat équivalent.
  • La personne qui valide les sorties (devis, relances, offres) est désignée.
5 · Erreurs fréquentes

Ce qui fait échouer un skill

SymptômeCause probableCorrection
Le téléversement est refusé sur claude.aiZip sans dossier racine, dossier renommé, description trop longue ou contenant un caractère invalideRefaire le zip depuis le dossier ; vérifier que le dossier porte exactement le name
Le skill n'est jamais utiliséDescription vague, ou exécution de code désactivéeReformuler la description avec vos mots ; vérifier le réglage Capacités
Le skill se déclenche à tortDescription trop large (« aide à rédiger »)Nommer le document produit et les situations précises
Claude invente un prix ou un tauxFichier compagnon resté incompletCompléter la grille ; la procédure demande déjà de signaler les trous
Un collègue n'a pas le skillSur claude.ai, un skill est personnel par défautChacun l'installe, ou partage d'organisation sur Team/Enterprise, ou plugin (chapitre 7)
Le skill marche sur claude.ai, pas dans Claude CodePas de synchronisation entre surfacesCopier le dossier dans .claude/skills/
Deux versions circulent dans l'équipeChacun a modifié sa copieUn responsable du skill, une version de référence datée, un plugin pour la diffuser
Le frontmatter casse après modificationUn deux-points suivi d'une espace dans la descriptionReformuler sans « : », ou mettre la description entre guillemets

L'erreur de fond. Écrire un skill pour une tâche que personne ne fait de la même façon deux fois. Un skill fixe une procédure : si l'entreprise n'en a pas, le skill n'en crée pas. Écrivez d'abord la procédure avec la personne qui fait le travail, ensuite le skill.

6 · Sécurité et données

Un skill s'installe comme un logiciel

Anthropic le dit dans sa documentation : un skill donne à Claude des instructions, et parfois du code. Un skill malveillant peut lui faire utiliser ses outils d'une façon qui ne correspond pas à ce qu'il annonce, jusqu'à faire sortir des données.

Les règles que nous appliquons

  • N'installer que des skills de confiance : écrits par vous, par Anthropic, ou par un prestataire dont vous avez lu le travail. Les 8 skills de ce pack sont du texte seul : aucun script, aucun appel réseau. Lisez-les quand même, c'est rapide.
  • Lire tous les fichiers d'un skill tiers avant de l'installer, pas seulement le SKILL.md. Méfiance envers tout script, toute adresse web, toute instruction du type « envoie », « transfère », « ignore ».
  • Se méfier des skills qui vont chercher du contenu en ligne : ce contenu peut contenir des instructions cachées, et une source fiable aujourd'hui peut changer demain.
  • Limiter les droits des connecteurs : un skill de tri d'e-mails n'a besoin que de lire. Les droits d'envoi et de suppression restent humains.
  • Garder une validation humaine sur tout ce qui engage l'entreprise : devis, relance, offre d'emploi, réponse client.

Données

  • Les fichiers compagnons contiennent vos prix et vos procédures : ce sont des informations d'entreprise. Préférez un compte Team ou Enterprise, sur lequel Anthropic indique ne pas entraîner ses modèles par défaut sur les données de ses offres commerciales.
  • Pour les comptes Free, Pro et Max, un réglage d'entraînement existe dans les paramètres de confidentialité : vérifiez-le.
  • Ne mettez dans un skill ni mot de passe, ni clé d'accès, ni donnée personnelle de client ou de salarié.
  • D'après la documentation développeurs, les skills ne sont pas couverts par les accords de conservation zéro des données (ZDR) proposés sur l'API.

Pour une organisation Enterprise. Anthropic propose une analyse du contenu des skills téléversés sur claude.ai. Elle ne remplace pas la relecture humaine, et elle ne couvre pas les skills envoyés par l'API.

7 · Aller plus loin

Du skill personnel au plugin d'équipe

Un skill installé par chacun, à la main, convient à une personne ou à une équipe de trois. Au-delà, les versions divergent. La réponse d'Anthropic s'appelle un plugin.

Un plugin est un paquet qui regroupe des skills, des connecteurs vers vos outils et, selon les surfaces, des sous-agents, des commandes et des automatismes. Sur les offres Team et Enterprise, l'organisation peut publier ses plugins dans une marketplace privée et choisir, pour chacun, s'il est installé par défaut, disponible, requis ou indisponible. Une modification faite une fois arrive chez tout le monde.

SituationLa bonne forme
Une personne, une tâche répétéeUn skill personnel, installé à la main
Une petite équipe, un projet de codeDes skills de projet versionnés dans .claude/skills/
Plusieurs équipes, des skills qui doivent rester identiquesUn plugin privé, diffusé par l'administration
Un skill qui doit lire ou écrire dans vos outils (CRM, facturation, messagerie)Un plugin qui associe le skill et le connecteur, avec des droits limités

Quand le faire vous-même, quand vous faire aider

Seul, si vous avez une procédure déjà écrite, une ou deux personnes concernées, et le temps de faire les trois essais. Ce pack est fait pour ça.

Accompagné, quand la procédure n'existe que dans la tête d'une personne, quand plusieurs équipes doivent partager les mêmes skills, quand il faut brancher un outil métier, ou quand des données sensibles circulent. Le travail consiste alors à observer le processus, l'écrire, tester sur vos cas réels et déployer par plugin, avec un responsable désigné chez vous.
